## Directory structure

```
/opt/
├── ciatec-ai/              # Python projects — one subdirectory per project
│   └── <project_name>/     # GitHub repository clone
└── fuseki/                 # Apache Jena Fuseki
    ├── data/               # Fuseki datasets
    ├── run/                # Fuseki runtime base dir
    └── fuseki-server       # main binary

/etc/nginx/
├── sites-available/
│   ├── default             # main config — SSL, domain, includes ai-projects/
│   └── ai-projects/        # one .conf per project (written by new-ai-project.sh)
└── sites-enabled/
    └── default -> ../sites-available/default

/var/log/ciatec/
└── deploys.log             # deploy / provision history

/home/ubuntu/
└── actions-runner/         # GitHub Actions Runner
```

## Nginx

### Main config

```
/etc/nginx/sites-available/default
```

The 443 server block includes all project configs:

```nginx
include /etc/nginx/sites-available/ai-projects/*.conf;
```

### Test and reload

```bash
sudo nginx -t
sudo systemctl reload nginx
```

### Per-project config (generated by script)

```
/etc/nginx/sites-available/ai-projects/<project_name>.conf
```

Generated content (matches `new-ai-project.sh`):

```nginx
location /<project_name>/ {
    proxy_pass         http://127.0.0.1:<port>/;
    proxy_set_header   Host $host;
    proxy_set_header   X-Real-IP $remote_addr;
    proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header   X-Forwarded-Proto $scheme;
}
```

## Deploy or update a project

### Option A — GitHub Actions (`deploy-ai-project.yml`)

**Manual (from `ciatec-devops`):** Actions → **Deploy AI Project** → `project_name` + `port`.  
When run from `ciatec-devops`, the GitHub repo defaults to `ciatec-org/<project_name>`.

**From a product repo** (create or update on every push to `main`):

```yaml
name: Deploy

on:
  push:
    branches: [main]

jobs:
  deploy:
    uses: ciatec-org/ciatec-devops/.github/workflows/deploy-ai-project.yml@main
    with:
      project_name: project-name
      port: 8001
```

When called from another repo, the workflow uses `github.repository` as the clone source.

The workflow then:

1. Checks out `ciatec-org/ciatec-devops@main`
2. Runs `sudo bash scripts/setup/new-ai-project.sh <name> <port> <org/repo>`
3. Checks `systemctl is-active <project_name>`
4. Polls `http://127.0.0.1:<port>/health` for HTTP 200 (default: 12 attempts, 5s apart)
5. Appends a line to `/var/log/ciatec/deploys.log`

### Option B — script on the host

```bash
sudo /path/to/ciatec-devops/scripts/setup/new-ai-project.sh <project_name> <port> ciatec-org/<repo>
```

The script will:

1. Clone (or `git pull --ff-only` on `main`) into `/opt/ciatec-ai/<project_name>/`
2. `chown` to `ubuntu:ubuntu`
3. `pip install -r requirements.txt` when present
4. Write/enable/restart the systemd unit (`uvicorn main:app`)
5. Write the Nginx location under `ai-projects/` and reload Nginx

## Runner sudoers

```
/etc/sudoers.d/ciatec-runner
```

Documented baseline:

```
ubuntu ALL=(ALL) NOPASSWD: /usr/bin/systemctl, /usr/sbin/nginx, /usr/bin/tee, /bin/mkdir
```

`deploy-ai-project.yml` runs `sudo bash scripts/setup/new-ai-project.sh`. That baseline **does not** cover the script (clone under `/opt/ciatec-ai`, writing systemd units, `pip`, etc.). Before the first deploy via Actions, either:

- grant NOPASSWD for that script path (adjust for the runner workspace), or
- run the script once with a user that already has full sudo.
